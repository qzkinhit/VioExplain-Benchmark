# 实验工件和日志约定

复现者从运行命令进入实验，先核对任务定义和数据划分，再读取逐样本结果。汇总数字应能沿着文件散列追溯到预测、拟合参数、实际源码和输入。

| 阶段 | `result/` 中保留的工件 | `log/` 中保留的证据 |
| --- | --- | --- |
| 输入核验 | 数据卡、split/window清单、源码与模型SHA256、锁定配置 | 实际读取路径、允许的数据分区、范围与hash核验结果 |
| 拟合 | 仅fit估计的缩放参数、约束、知识、投影或匹配头 | 样本量、每类/运行/井支持、拟合起止时间与异常 |
| 编码与中间量 | 特征缓存清单及哈希、缺失mask、有效位置、原型来源 | 逐批进度、有效/缺失数量、编码回退原因、耗时 |
| 解释 | 全部窗口的违反、候选、匹配代价、原型和证据指派 | 候选为空、图漏失、背景分配、求解状态及回退次数 |
| 评价 | 完整预测、逐类/机器/运行/井结果、汇总、区间定义 | 评价范围、排除原因、有效分母、指标检查 |
| 完成或失败 | `COMPLETE.json`或失败记录，全部小工件索引 | 真实退出码、完整标准输出/错误、运行时长 |

上述约定用于新开发版本。历史运行按实际已保存内容披露，不能为满足格式补造当时不存在的中间输出。大型特征或权重可保存在远端，必须提供文件大小、SHA256、生成命令及获取方式；本地结果清单应明确标注尚未下载。

公开入口可使用以下命令保留独立控制台日志。具体模型仍负责逐阶段研究工件，外层包装只记录进程和来源。

```bash
python -m run_vioexplain.logged_runner formal statistical \
  --dataset smd --data data/raw/smd --output result/runs/smd-statistical
```

每次执行使用新的日志ID。返回非零退出码时保留日志，不创建科学验证成功标记。运行配置、模型身份和数据划分一旦变更，应使用新结果目录，保留原失败和选择历史。只有论文对应的方法协议锁定后，才能进行独立校准和测试。

公开前要将用户路径转换为相对路径并审查敏感字段，同时保留原日志哈希与脱敏说明。不能把本地`log/remote`和整个`result/research`直接上传。
